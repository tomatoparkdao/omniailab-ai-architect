# 设计汇报方法论

设计汇报方法论解决的是"好设计如何被理解、被信任、被决策"。它把专业成果转译为不同受众可消化的叙事结构：概念怎么讲、平面怎么讲、造价怎么讲、风险怎么讲。本领域是各专业成果与决策者之间的翻译层。

本领域给出的是**表达与沟通的通用框架**，不改变设计本身。任何汇报中的安全与合规内容，仍须由持证专业人员在项目所在地复核签署。

## 适用范围与边界

- 适用：方案汇报结构、图册组织、图面表达、术语统一、决策引导、风险告知。
- 适用：S2 概念汇报、S4 深化汇报、S6 定稿汇报、S8 交付说明。
- 不适用：设计内容的生成与校核（由各领域负责）。
- 不适用：替代法定审查说明。
- 边界：表达服务于决策，不夸大、不隐瞒、不制造误解。
- 边界：对未决项与风险必须显式呈现，而非回避。

## 核心判据

1. 汇报有清晰的叙事主线：问题—策略—方案—结论。
2. 每个方案页面回答一个明确问题。
3. 图面表达与口头说明一致，无矛盾。
4. 术语全篇统一，不混用同义词。
5. 数字（面积、造价、层高）有统一来源与口径。
6. 概念描述落到功能、尺度、材料、照明四个可验证维度。
7. 方案比较以同一标准、同一格式呈现。
8. 未决项与风险被显式列出。
9. 决策点被明确标注，引导业主拍板。
10. 图纸比例与可读性适合汇报场景。
11. 关键数值以图表或标注呈现，而非口头带过。
12. 汇报材料有版本号与日期。
13. 对受众分层：业主、评审、施工方各有侧重。
14. 结尾有明确的下一步与责任分工。
15. 不使用无法被图纸支撑的形容词。
16. 不使用绝对化承诺（如"绝对安全""零风险"）。
17. 安全与合规内容标注待专业复核。
18. 造价相关内容说明口径与假设。
19. 图册目录与实际页面一致。
20. 重点方案有放大或剖切说明。
21. 复杂空间用剖面或轴测辅助理解。
22. 对业主关切的问题集中回应。
23. 汇报时长与页数匹配，不堆砌。
24. 关键结论可被复述（一句话结论）。
25. 汇报后形成会议纪要与待办。
26. 图面色彩与风格统一，不喧宾夺主。
27. 呈现不确定性的方式诚实且建设性。
28. 对比方案的差异点可被快速识别。
29. 交付说明包含使用与维护要点。
30. 所有安全与合规结论均标注待持证专业人员复核签署。

## 数值与区间

以下均为**常见表达惯例区间**，非强制标准，须结合场景调整。

| 项目 | 常用取值 | 说明 |
| --- | --- | --- |
| 每页信息点 | 1–3 个 | 避免过载 |
| 单页文字量 | 精炼为宜 | 以图为主 |
| 汇报页数（概念） | 15–30 页 | 视复杂度 |
| 汇报页数（深化） | 20–40 页 | 视复杂度 |
| 单页停留时间 | 30–90 秒 | 视内容 |
| 平面图比例（汇报） | 1:100 / 1:200 | 便于观看 |
| 效果图数量 | 每主空间 1–2 张 | 视重点 |
| 方案对比数 | 2–3 个 | 便于决策 |
| 结论页数 | 1–2 页 | 一句话结论 |
| 风险条目 | 逐条列出 | 不隐瞒 |
| 未决项条数 | 明确可数 | 指定决策人 |
| 版本号 | 主.次.修订 | 统一 |
| 一页图表数 | 1–4 个 | 便于阅读 |
| 术语表 | 按需附上 | 统一口径 |

## 常见错误

- 只讲概念美感，不讲功能与代价。
- 页面信息过载，重点被淹没。
- 图与口头说明不一致。
- 术语混用，业主理解混乱。
- 数值来源不一，前后矛盾。
- 概念描述无法验证。
- 方案比较标准不一致。
- 回避未决项与风险。
- 决策点模糊，业主不知拍什么板。
- 图纸比例不适，汇报时看不清。
- 关键数值只在口头提，材料里没有。
- 材料无版本号，版本混乱。
- 对所有人用同一套讲法。
- 结尾无下一步与分工。
- 用"绝对""零风险"等不可兑现措辞。
- 宣称合规却无专业复核支撑。

## 分阶段应用

- S2：讲清"问题与策略"，概念方向对比。
- S4：讲清"方案与代价"，功能与造价匹配。
- S6：讲清"定稿与协调"，接口与净高。
- S8：讲清"交付与维护"，使用说明。
- 每阶段结尾给出明确的下一步与责任分工。

## 典型权衡与取舍

- 信息全面 vs 重点突出：全面易失焦，突出易遗漏。
- 视觉冲击 vs 信息准确：冲击易牺牲严谨。
- 乐观表达 vs 风险告知：过度乐观损害信任。
- 页数多 vs 时长有限：页多讲不完。
- 统一模板 vs 个性表达：统一高效，个性贴合。

## 输出物与数据格式

- 汇报图册（含目录与版本号）。
- 方案对比页。
- 关键数值表。
- 风险与未决项清单。
- 结论页（一句话结论 + 下一步）。
- 会议纪要与待办。

## 风险与不确定性

- 受众理解差异导致误读。
- 未决项被忽略导致后期争议。
- 表达夸大导致期望管理失败。
- 版本混乱导致用错图。
- 合规内容被误认为已确认。
- 以上风险须通过版本管理与显式标注控制。

## 术语与口径

- **叙事主线**：问题—策略—方案—结论。
- **一句话结论**：可被复述的核心判断。
- **决策点**：需业主拍板的具体事项。
- **未决项**：需外部输入的事项。
- **风险告知**：对不确定性的事实性说明。
- 上述口径跨文档统一使用。

## 与相关规范的衔接方式

- 本领域不引用具体条文号，只描述"项目所在地现行规范"。
- 汇报中涉及的合规内容一律标注"待专业复核"。
- 不得以汇报结论替代专业签署。
- 涉及安全与合规的最终判定交由持证专业人员签署。

## 汇报结构模板

- 第一段：项目背景与核心问题。
- 第二段：设计策略与约束条件。
- 第三段：方案呈现（功能—流线—界面）。
- 第四段：造价与实现路径。
- 第五段：风险与未决项。
- 第六段：结论与下一步。
- 每段以一页结论页收口，便于记忆。

## 受众分层策略

- 业主决策层：关注价值、造价、风险与决策点。
- 评审专家：关注合规、逻辑、接口与遗漏项。
- 施工方：关注尺寸、节点、材料与做法。
- 运营方：关注维护、检修与使用便利。
- 对每类受众调整详略与术语深度。

## 常见问答式判断

- 问：这个概念怎么讲？答：落到功能、尺度、材料、照明四点。
- 问：造价怎么讲？答：说明口径、假设与区间。
- 问：风险要不要讲？答：必须讲，且给出应对。
- 问：未决项怎么处理？答：列出并指定决策人。
- 问：结论怎么收？答：一句话结论加下一步。
- 以上问答用于保证汇报可决策。
