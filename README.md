# OmniArchitect

**AI 建筑 / 室内设计总设计师** — 八阶段专业工作流 · 28 项专业能力 · 可真正执行的工具适配器 · 一份统一空间数据

> 判断这个项目是否成立的唯一标准：
> 能不能真正读取一个住宅项目的数据、输出两套平面方案、生成**有效的 DXF**、构建**可编辑的 3D 场景**，并在用户改尺寸后**同步更新**。
> 不是"能聊设计"。

---

## 它做什么

| | |
|---|---|
| **业务阶段** | 八阶段：任务书 → 概念 → 平面 → 初步设计 → 表现 → 定稿 → 施工图 → 交付，每阶段带人工确认门禁 |
| **专业能力** | 28 项，可跨阶段调用（灯光设计同时服务概念、初步设计与灯具定位） |
| **工具执行** | DXF（内置 R12 写出器 + ezdxf）、OBJ/MTL、Blender 脚本、IFC、FreeCAD 脚本 |
| **变更管理** | 诊断 → 影响面 → 回流计划 → 门禁重开；几何变更全局失效重算，饰面变更不动几何 |
| **质量门** | 几何、人体工学、采光、规范初审；不确定构件一律阻断 |

## 快速开始

```bat
set PYTHONPATH=E:\SKILL\建筑室内设计skill
cd /d E:\SKILL\建筑室内设计skill\omniarchitect

python -m omniarchitect doctor          :: 本机工具链体检
python -m omniarchitect demo --out out  :: 生成示例项目并跑通全部八阶段
python scripts/run_tests.py             :: 65 项测试
```

不需要安装任何包。`doctor` 会告诉你哪些工具缺失，以及每一项的降级方案。

## 变更影响分析（核心能力）

```
输入：我不喜欢客厅的电视背景墙

一、诊断
  判定领域：立面与造型（置信度 95%）
  落点阶段：04 初步设计与方案深化
  是否改变几何：否
  处理原则：只改该立面的分缝、比例与材料，平面与结构不动

二、影响范围   空间 SA-LIVING，构件 2 个，成果 6 项
三、保持不变   art-delivery / art-materials / art-freeze …
四、回流计划   S4 做法 → S5 重出图 → S6 重审定 → S7 重出图 → S8 重算量
五、需重新确认 初步设计确认 / 表现成果确认 / 设计锁定 / 施工图审查 / 交付验收
```

对比一下几何变更：

```
输入：把厨房和餐厅之间的墙往外移 300mm
  判定领域：平面尺寸与墙体　落点 S3　改变几何：是
  回流：S3 → S8（平面的一切推论全部重来）
```

**饰面变更不碰几何，几何变更一定连带全部下游。** 这条规则有测试守着。

## 三条最容易被搞错的专业逻辑

1. **概念与平面可交互迭代，但业主确认功能需求前不得开始精细建模。**
2. **CAD 不是最后才画**——方案深度图自初步设计（S4）起就画，区别在 `schematic` 与 `construction` 两个深度，不是有没有图纸。
3. **成本估算从前期就动态进行**（S1 起就有估算），深化完成后才形成正式清单。

## 边界

结构安全、消防、无障碍、机电负荷与当地法规符合性**不在本系统结论范围内**，须由持证专业人员在项目所在地复核签署。方案深度成果不得当作施工图使用；生成式图像不得作为尺寸依据。
