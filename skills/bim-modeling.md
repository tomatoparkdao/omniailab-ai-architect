# BIM 建模

## 做什么

把统一空间模型（Canonical Spatial Model）翻译成**参数化**构件与信息模型：几何、属性、关系三者统一，可出图、可算量、可协同。与 3D 空间建模的关键区别在于——BIM 承载**构件参数与信息**，不是只有几何外壳。**网格 ≠ 参数化 BIM**：OBJ / MTL 网格不具有构件类型、属性与 IFC 语义。缺少 IfcOpenShell 时，只能输出「IFC 投影数据 + 生成脚本」并标 `degraded`。

## 什么时候用 / 不用

| 用 | 不用 |
|---|---|
| 需要按 LOD 分级建立带参数的构件模型（S5 / S7） | 结构分析与配筋计算结论 |
| 需要模型与图纸、明细表同源，避免双重维护 | 机电系统计算与负荷核算 |
| 需要门窗、房间等参数化统计与明细表 | 生成写实效果图或漫游（见 scene-rendering / walkthrough） |
| 需要多专业合模与碰撞检查（S7） | 判定消防、无障碍与法规符合性是否达标 |
| 需要导出开放格式用于交付与协同 | 用网格场景宣称具备 IFC 与信息属性 |

## 输入 → 输出

| 输入 | 输出 |
|---|---|
| 统一空间模型当前修订 | `model.ifc`（存在 IfcOpenShell 时；否则降级，见下） |
| 精度等级要求（LOD100–LOD400） | `ifc-projection.json` + `build-ifc.py`（无 IfcOpenShell 时，标 `degraded`） |
| 构件命名与属性字典 | `component-schedule.json`（门窗 / 房间 / 材料明细） |
| 材料属性与规格 | `clash-report.json`（碰撞检查记录） |
| 楼层标高与轴网（与建筑一致） | `lod-spec.json`（精度等级与用途说明） |
| 机电点位与专业模型（S7） | `model-manifest.json`（单位、原点、修订、构件来源）+ 待复核项清单 |

## 操作步骤

1. 建立统一轴网、标高与唯一坐标原点，单位取 mm，与制图标准一致。
2. 确定精度等级与用途（LOD100–LOD400），编写 `lod-spec.json` 与命名属性字典。
3. 按"先结构、后建筑、再机电"顺序建构件，并赋予材料、编号、类别属性。
4. 划分房间与空间，门窗等构件参数化，使其可统计数量与规格。
5. 生成平面、剖面与明细表派生视图，确保模型与图纸同源。
6. 多专业合模并执行碰撞检查，留存 `clash-report.json`；写待复核项。
7. 交付前做几何与信息双重检查；导出 IFC——无 IfcOpenShell 时输出投影数据与生成脚本并标 `degraded`。

## 判断清单（可判定的判据）

以下均为**常见建模惯例与精度分级**，非当地法定强制值，须以委托方建模标准为准。

| 判据 | 判准 |
|---|---|
| 单位与坐标 | 统一 mm，原点唯一，与制图 / 几何模型同坐标系 |
| 精度分级 | LOD100 体量 / LOD200 方案 / LOD300 施工图 / LOD350 深化 / LOD400 加工（常见工程惯例区间） |
| 构件属性 | 每个构件可查询类型、材料、编号与类别 |
| 模型与图纸同源 | 与图纸、材料表口径一致，不一致即为缺陷 |
| 参数化程度 | 门窗等构件可统计数量与规格 |
| 碰撞检查 | 已执行并留记录，容差按净空要求 |
| 合模频率 | 每日或每周（常见工程惯例区间） |
| 导出格式 | 存在 IfcOpenShell 时出 `model.ifc`；否则出投影数据 + 脚本并标 `degraded` |
| 深度命名 | 不得把网格场景或投影数据声明为完整 IFC 信息模型 |

## 硬性规则

1. **网格 ≠ 参数化 BIM**：OBJ / MTL 网格不得称为 BIM；本能力必须承载构件参数与信息属性。
2. **IFC 能力如实标注**：无 IfcOpenShell 时，只能输出「IFC 投影数据 + 生成脚本」并标 `degraded`，不得声称已生成可用的 IFC 模型。
3. **模型同源**：模型与图纸、明细表须同源，禁止各自维护；不一致即视为缺陷并阻断。
4. **免责边界**：结构安全、消防、无障碍、机电负荷与法规符合性不在本能力结论范围内，相关构件信息标注待持证专业人员在项目所在地复核签署。
5. 交付格式按接收方要求，兼顾原生与开放格式；不确定信息标 `uncertain = true` 并作阻断项。
6. 设计锁定（S6）后不得局部手改模型，须走变更影响分析并同步校核碰撞与净高。

## 常见坑

| 坑 | 后果 | 怎么避 |
|---|---|---|
| 把 OBJ 网格当 BIM 交付 | 无法统计构件与信息，被误认为信息模型 | 明确网格≠BIM，参数化构件另建 |
| 无 IfcOpenShell 却宣称已出 IFC | 交付失信，接收方打不开或信息缺失 | 如实标 `degraded`，交付投影数据 + 脚本 |
| 单位 / 坐标不统一 | 合模错位，出图整体偏移 | 先定轴网、标高与原点 |
| 模型与图纸各改各的 | 版本不一致，下游误用 | 模型同源，变更后重新校核 |
| 精度超标或不足 | 文件沉重或信息不足，与用途不匹配 | 按用途选 LOD，避免盲目堆精度 |
