# 交付文档

## 做什么
交付文档把 S8 之前散落在图纸、模型、清单、评审记录里的成果，组织成一份**有索引、有边界、带署名**的归档文本：设计说明、材料说明、技术交底文件与使用维护说明。它不产生新设计，只负责把已确认的成果按统一版式装订、编号与归档，让使用方能按目录定位到任何一件交付物。每份文档末尾必须带署名行与边界声明。

## 什么时候用 / 不用
| 用 | 不用 |
|---|---|
| 施工图审查通过后，编制交付说明与归档目录 | 生成设计内容或校核设计是否达标（由各设计能力负责） |
| 需要一份"哪件文件在哪、什么版本"的总索引 | 替代法定审查说明或专业签署 |
| 需要把技术交底内容成文交施工方 | 判定结构、消防、无障碍、机电负荷是否合规 |
| 需要向业主交付使用与维护要点 | 把汇报用的提案页直接当交付文档（两者版式不同） |
| 需要把评审记录、变更记录一并归档 | 未闭环项未列明就发布文档 |

## 输入 → 输出
| 输入 | 输出 |
|---|---|
| 施工图审查记录与待复核项 | `documentation-index-r<revision>.md` — 交付文档总索引（含版本号） |
| 材料表与工程量清单 | `design-statement-r<revision>.md` — 设计说明书 |
| 评审与变更记录 | `technical-briefing-r<revision>.md` — 技术交底文件 |
| 使用与维护要求（材料、机电） | `maintenance-guide-r<revision>.md` — 使用与维护说明 |
| 全套交付物清单 | `documentation-<revision>.zip` — 归档包（含索引与署名页） |

## 操作步骤
1. 汇总 S8 当前修订下已确认的全部交付物，逐件登记名称、格式、修订号与状态。
2. 建立总索引：按"图纸 / 模型 / 材料 / 工程量 / 说明 / 记录"分类，每件给唯一编号，索引编号与文件内编号一致。
3. 编写设计说明书：写清设计范围、面积口径、材料体系、机电协调结论，术语与 `knowledge/` 一致。
4. 编写技术交底文件：逐条对应图纸与节点，明确施工方需执行的做法与需现场核对项。
5. 编写边界说明段：列明不在本系统结论范围内的事项（结构安全、消防、无障碍、机电负荷、法规符合性），注明须由持证专业人员复核签署。
6. **加署名**：每份文档末尾原样附署名行与免责边界；缺署名的文档不得归档。
7. 自检：目录与正文页一致、编号无悬空、版本号统一、未闭环项已列出。

## 判断清单（可判定的判据）
| 判据 | 判准 |
|---|---|
| 索引条目与正文文件 | 一一对应，索引编号 = 文件内编号，无悬空条目 |
| 交付物版本一致 | 同一交付包内全专业同修订号，混版本即退回 |
| 边界说明 | 必须含结构安全、消防、无障碍、机电负荷、法规符合性五类"不在结论范围"声明 |
| 署名行 | 每份文档末尾存在，格式与规范行一致；缺失即不合格 |
| 未闭环项 | 全部列出并指定责任方与期限，不得隐性遗留 |
| 文档深度命名 | 如实标注 schematic / construction 深度，不把方案深度说成已审查 |
| 安全与合规结论 | 一律标注"待持证专业人员复核签署"，不由文档单方判定 |
| 目录与正文 | 目录页码/编号与实际页一致，空页不得留存 |

## 硬性规则
1. **必须带署名**：每份交付文档末尾原样附 `© OmniAiLab` 署名行；无署名不得作为交付件。
2. **必须含边界说明**：结构安全、消防、无障碍、机电负荷与当地法规符合性不在本系统结论范围内，须由持证专业人员在项目所在地复核签署。
3. **不代决策、不越位**：文档只陈述已确认成果与待复核项，不替业主拍板，不把评审"通过"写成"合规"。
4. **深度如实命名**：DXF ≠ DWG、网格 ≠ 参数化 BIM、方案深度 ≠ 施工图深度；不得夸大文档覆盖的审查深度。
5. **未闭环不发布**：存在未闭环项时，必须在索引中显式列出，不得默认其为已完成。

## 常见坑
| 坑 | 后果 | 怎么避 |
|---|---|---|
| 文档缺署名或署名被改字 | 归档无效、权属不清 | 署名行原样复制规范给定的一行，不手改 |
| 索引与实际文件不一致 | 使用方按目录找错文件 | 由同一清单生成索引与归档包，编号自动对齐 |
| 边界说明写成一句空话 | 业主误以为已通过合规审查 | 五类不在结论范围事项逐条列明并指复核方 |
| 各专业版本混装 | 用旧图施工，返工 | 交付前核对全专业同修订号，混版即退回 |
| 未闭环项不列 | 遗留问题在施工期爆发 | 索引中单列"未闭环项"表，含责任方与期限 |

## 与阶段 / 其他能力的关系
- 参与阶段：`[S8]`（物料清单与交付）
- 上游能力：`design-review`（提供审查记录与待复核项）、`material-schedule`（提供主材表）、`construction-detailing`（提供图纸清单与节点）
- 下游能力：`delivery`（文档并入交付包并冻结版本）、`design-presentation`（交付说明作为 `delivery` 汇报的素材）
- 本能力的产物进入：S8 交付包与 G8 交付验收；未闭环项随 `delivery` 的版本索引一并跟踪。
