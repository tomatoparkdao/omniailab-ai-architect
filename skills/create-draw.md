# 概念图解与评图

## 做什么
用约定的图形语义把设计判断画出来：概念图解说清"主张—原型—策略"，评图用统一批注色彩标出问题、方向、光与亮点，使一张图能被快速读懂，且改图能跨轮追踪。

## 什么时候用 / 不用
| 用 | 不用 |
|---|---|
| 需要把概念讲成一张可读的图 | 出正式施工图与节点详图 |
| 评图要给意见并区分问题等级 | 判定结构安全或消防合规结论 |
| 概念 / 平面 / 深化阶段需要方向图解 | 替代尺寸标注与几何校核 |
| 要跨轮对比同一方案的改动 | 出效果图或渲染成品 |

## 输入 → 输出
| 输入 | 输出 |
|---|---|
| 概念主张与空间原型 | `concept-diagram.png` — 概念图解（三段式） |
| 当前平面 / 深化方案 | `review-annotated.png` — 批注评图（红蓝橙绿灰） |
| 上一轮评图意见 | `annotation-ledger.md` — 批注台账（逐条核销） |
| 光、材质、动线策略 | `strategy-overlay.png` — 策略叠加图 |
| 方案修订版本号 | `create-draw-r{n}.pptx` — 图解与评图汇报页 |

## 操作步骤
1. 按色彩语义批注：红 = 问题与张力、蓝 = 方向动线与视线、橙 = 光的动作、绿 = 亮点、灰 = 参考。
2. 概念图解按三段式组织：概念主张 + 空间原型 + 光 / 材质 / 动线三策略。
3. 图主文辅：图上标签 ≤12 字，说明栏每条 ≤30 字。
4. 评图时每个问题指向具体图纸、构件或数值，不写笼统结论。
5. 把意见转成台账条目：编号 + 描述 + 严重度 + 责任方 + 期限。
6. 下一轮先查上轮遗留项，再评本轮变更项。
7. 出具 `create-draw-r{n}` 作为评审与汇报材料。

## 判断清单（可判定的判据）
| 判据 | 判准 |
|---|---|
| 色彩语义唯一 | 红 / 蓝 / 橙 / 绿 / 灰 五种语义互不混用，一种颜色只表达一种含义 |
| 图解三段式 | 概念主张 + 空间原型 + 三策略齐备，缺段不成立 |
| 标签字数 | 图上标签 ≤12 字，说明栏每条 ≤30 字 |
| 意见可执行 | 每条意见指向具体图纸、构件或数值，可被逐条核销 |
| 严重度分级 | 意见分严重度（阻断 / 重要 / 一般）并指定责任方与期限 |
| 跨轮可追踪 | 上轮遗留项在本轮图上有可见处理痕迹 |
| 图与说明一致 | 图面表达与说明文字一致，无"图上有、说明无"或反之 |

## 硬性规则
1. **图像不作尺寸依据**：批注图与概念图解均为示意材料，不构成几何或尺寸依据。
2. 评图不判定结构安全、消防、无障碍与机电负荷，此类项只标注"须由持证专业人员复核签署"。
3. 批注不得覆盖原始几何信息，避免他人误读尺寸。
4. 不把示意图说成效果图，不把评图说成施工图审查。
5. **不代业主决策**：给出推荐方向与备选，不写"怎么都行"。
6. 平台未接入时只交付图解任务包并标 `awaiting_platform`，绝不写占位图、绝不改道第三方。

## 常见坑
| 坑 | 后果 | 怎么避 |
|---|---|---|
| 颜色语义混用 | 图越画越看不懂 | 一色一义，全项目统一 |
| 图上贴满长文字 | 图被文字淹没 | 标签 ≤12 字，说明另附 |
| 意见笼统 | 无法整改与核销 | 每条指向具体构件或数值 |
| 批注盖住尺寸 | 下游误读几何 | 批注置于留白或独立图层 |
| 只评本轮不查遗留 | 老问题反复出现 | 先查遗留，再评本轮 |
