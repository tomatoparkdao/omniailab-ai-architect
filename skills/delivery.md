# 版本管理与交付

## 做什么
版本管理与交付把整套成果收敛成一个**可核对、可追溯、可签收**的交付包：给每件成果打修订号，变更落地时沿下游链条做失效重算，生成交付包索引，并把未闭环项显式列出。它管的是"哪一版、改了什么、谁还没闭环、能不能冻结"，不产生新设计，也不替任何专业下结论。交付验收通过后冻结版本基线。

## 什么时候用 / 不用
| 用 | 不用 |
|---|---|
| 施工图审查通过，准备打包交付、编制包索引 | 生成或修改设计内容（由各设计能力负责） |
| 上游发生变更，需要判断哪些下游成果失效并重算 | 判定结构、消防、无障碍、机电负荷是否合规 |
| 需要冻结版本基线、记录变更台账 | 替业主决定是否接受交付物（由业主签收） |
| 需要给出"未闭环项还剩哪些、谁负责" | 把估算总额当结算依据 |
| 需要核对全专业是否同版本、能否签收 | 跳过审查直接把未冻结版本当交付件 |

## 输入 → 输出
| 输入 | 输出 |
|---|---|
| 各能力当前修订产物与变更记录 | `revision-log-r<revision>.md` — 变更台账（改了什么、为何改、影响谁） |
| 变更落点阶段与 `DOWNSTREAM` 链条 | `impact-report-r<revision>.json` — 失效重算清单（哪些产物需重出） |
| 全套交付物（图、模型、材料、工程量、文档） | `delivery-index-r<revision>.md` — 交付包索引（编号+名称+修订号+状态） |
| 全专业校核与评审结果 | `delivery-checklist-r<revision>.md` — 交付核对表（通过/退回） |
| 未闭环项与待复核项 | `open-items-r<revision>.md` — 未闭环项清单（含责任方与期限） |
| 通过核对的交付物集合 | `delivery-baseline-r<revision>.json` — 冻结版本基线快照 |

## 操作步骤
1. 汇总当前所有成果的修订号，建立"能力 × 产物 × 修订号"总表，任一处混版即标阻断。
2. 接收变更：确认变更落在哪个阶段，按下游链条判定失效范围，把受影响产物列入失效重算清单。
3. **失效重算**：受影响的产物必须重出并升修订号；未重算的旧产物不得进入交付包（禁止局部手改绕过）。
4. 生成交付包索引：按图纸/模型/材料/工程量/文档分类，逐件登记编号、名称、修订号与状态（含"待复核""未闭环"）。
5. **列出未闭环项**：所有待复核项、未决项、退回未闭环项逐条列出，指定责任方与期限；未闭环项不得隐藏。
6. 交付核对：核对全专业同版本、索引与实体一致、边界与署名齐备、未闭环项已列明；不通过则退回。
7. 核对通过后冻结版本基线并输出基线快照；业主签收后该修订号为交付基线。

## 判断清单（可判定的判据）
| 判据 | 判准 |
|---|---|
| 修订号格式 | 主.次.修订 三段制，全专业统一，不混用 |
| 全专业版本一致 | 交付包内同修订号；混版本即退回 |
| 失效重算闭环率 | 100%，受影响产物全部重出且已升修订号 |
| 局部手改 | 0 例，变更一律走失效重算链 |
| 索引与实体 | 索引每一条都能定位到真实文件，无悬空编号 |
| 未闭环项 | 全部在 `open-items` 中列出，含责任方与期限，数量可为 0 但不得缺项 |
| 交付核对结论 | 通过 / 退回二值明确，退回须写理由；不留"基本可行" |
| 安全与合规结论 | 一律标注"待持证专业人员复核签署"，不由交付单方判定 |

## 硬性规则
1. **版本冻结后不局部手改**：冻结后任何修改都走变更影响分析；直接改图或清单即视为版本失真，须重出。
2. **不虚构交付状态**：未重算的产物不得标"已更新"；索引状态必须与实体一致，禁止以旧版冒充新版。
3. **未闭环项必须列出**：待复核、未决、退回未闭环项一律显式列出并指明责任方，不得隐性遗留。
4. **不代决策、不定合规**：交付只做核对与冻结，是否签收由业主决定；结构、消防、无障碍、机电负荷与法规符合性不在本系统结论范围，须由持证专业人员复核签署。
5. **深度如实**：交付索引须如实标注 depth（schematic / construction）与产物性质（DXF / DWG、网格 / IFC、估算 / 结算），不夸大。

## 常见坑
| 坑 | 后果 | 怎么避 |
|---|---|---|
| 上游改了、下游没重算 | 用旧版交付，施工对不上 | 按下游链条强制失效重算，旧产物不出包 |
| 冻结后局部手改 | 版本失真、索引与实体不符 | 修改一律走变更影响分析并升修订号 |
| 交付包混版本 | 各专业图纸版本不一，返工 | 交付核对先卡"全专业同修订号" |
| 未闭环项不列 | 遗留问题在签收后爆发 | `open-items` 单列，含责任方与期限，核对前必查 |
| 索引手写与实际脱节 | 使用方找错文件 | 索引由交付物清单自动生成，编号自动对齐 |

## 与阶段 / 其他能力的关系
- 参与阶段：`[S8]`（物料清单与交付）
- 上游能力：`documentation`（提供交付文本与索引）、`material-schedule`（提供物料表）、`quantity-takeoff`（提供工程量清单）、`design-review`（提供审查与待复核记录）
- 下游能力：`design-presentation`（交付汇报 `delivery`）以冻结基线为准；业主签收推进 G8 交付验收
- 本能力的产物进入：S8 交付包与 G8 交付验收；变更落地时由本能力驱动全链失效重算。
