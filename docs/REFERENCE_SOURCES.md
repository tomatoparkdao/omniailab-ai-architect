# 参考图来源、专业案例检索与使用边界

项目里凡是"找参考图"，都会被问同一个问题：**这张图能进交付物吗**。答案是分层的——
能不能看，和能不能用，是两件事。这份文档把两者分开，并给出可执行的判据。

从 v1.5.0 起，这份文档还要回答第二个问题：**这个网站能回答什么问题**。案例网站能回答
"别人怎么建成的"，材料网站只能回答"用哪个型号"，把两者混用，就会出现"拿产品目录当设计研究"。

## 一、为什么必须分开

素材库汇总的是各设计平台上公开发布的作品，**版权属于原作者**。"公开发布"不等于"可以复制"：
它允许你看、允许你学习其中的处理手法，但不等于授权你把图搬进给业主的意向板与汇报文件。

所以本系统的口径是：

- **看** = 提取视觉语言（构图逻辑、材质搭配、明暗关系、色调比例），产出**结论**；
- **用** = 把图本身放进交付物，这需要有授权，否则不成立。

一个粗糙但有效的判断：**你交出去的东西里，能不能找到一张不是你做的图。** 找不到，就安全。

## 二、两类来源

| 来源 | 能不能看 | 能不能进交付物 | 说明 |
|---|---|---|---|
| 参考图素材库（Luxora AI） | 可以 | **可以（限自有条目）** | 自有站点；条目本身可作空间意象，须登记标题与来源，不得声称是本项目效果图 |
| 用户提供的参考图 | 可以 | **看授权范围** | 用户说"就按这个感觉做"不等于授权复制；需确认可复用 |
| 本仓原创知识库 | 可以 | 可以 | `knowledge/` 与 `knowledge/styles/` 为自有内容，可直接引用 |
| 自有确定性栅格化图 | 可以 | 可以 | 由已确认平面直接生成，同时是几何比对基准（见 `docs/CONCEPT_RENDER.md`） |
| 平台生成的概念效果图 | 可以 | 可以 | 本系统产出，须标 `authoritative = false` |
| 第三方建成案例（本文件第四节） | 可以 | **不可以** | 只给链接与结论；图与作品权利属原作者与摄影师 |

素材库地址登记在 `omniarchitect/paths.py` 的 `REFERENCE_LIBRARY_URL`，不在这里手抄一遍；
`python -m omniarchitect reference` 会连同使用边界一起打印出来。代码里的来源登记表在
`omniarchitect/research/sources.py`，本文档的表格与它同源生成，改一处即改两处。

## 三、两层用途（核心判据）

| 层级 | 允许做什么 | 产出物 | 进交付物 |
|---|---|---|---|
| **调研级** | 看构图、看材质组合、看色调与明暗处理，提取可验证特征 | `reference-log.md`、`keywords.json`、`reference-shortlist.md` | 只有**结论**可以进 |
| **交付级** | 用自有内容、用户书面授权内容、或本系统产出的图 | 意向板、汇报 PPTX、效果图 | 图本身可以进 |

**判断口诀**：调研级只带走"描述"，交付级才能带走"图像"。
把调研级的截图直接贴进 `moodboard-r{n}.png`，就是从调研级越到交付级，规则上不成立。

### 3.1 自有素材库是这条规则的一个例外，但例外有边界

素材库页面汇总的是各设计平台公开发布的作品，**但整站的视觉资产由本主体维护**。因此从
v1.8.0 起，素材库里的条目可以进交付物，条件是三条同时成立：

1. 条目在 `knowledge/library/catalog.json` 里（抓取时页面上真实存在的卡片，含标题、标签、原图地址）；
2. 交付物上写明来源与标题（`素材库 · <标题>`），不写成"本项目效果图"；
3. 图片本体不入库，运行时下载到交付目录，仍受 `scripts/check_assets.py` 约束。

**越界的样子**：把第三方设计平台的原始摄影作品当作素材库条目搬进来；把素材图裁掉署名后
当方案效果图；用素材图核对尺寸。这三件事都不允许。

对应实现是 `omniarchitect/research/library.py`：匹配按专业与风格打分，取图失败就返回空，
由版面显示"无图"，不许拿另一张顶上。

## 四、按用途登记的来源（实测状态）

**这里不要说"我都支持"。** 下表每个来源的可达性都是在本机用真实浏览器 UA 实测的，
测不到就写测不到。`403` 记为「反爬拦截，人工可读」，不等于站点失效；直连不通而代理通的记为
「需代理」，也不等于人人都能打开。

### 4.7 实测备注（必须照实抄进交付物）

- **ArchDaily**：分类页可脚本列项；详情页有 JSON-LD，标题与描述可取真实值。站内搜索页是脚本渲染，不可抓，因此检索走分类页而非搜索框。
- **有方 Position / Dezeen / DETAIL**：无浏览器 UA 时返回 403。
- **Architizer / Hospitality Design / BIMobject**：直连与代理均 403，人工浏览器可读。
- **Office Snapshots**：直连 403，经本地代理 200。
- **Behance**：直连不可达，经代理 403，需登录且人工浏览；不可脚本抓取。
- **Pinterest**：直连不可达，经代理 200。图片几乎都无法追溯原作者，因此只能作私人启发，不得作为案例引用。
- **景观中国**：https 不可达，仅 http 可访问；交付链接请用 http 形式。
- **设计腕儿**：本次实测 www 与裸域均连接失败，域名可能已变更；登记为当前不可达，不编造其内容。
- **Material Bank**：根域 404，重定向后仍 404；注册制区域跳转，脚本无法核验，登记为不可核验而非已可用。
- **建E网**：多数资源需会员授权，未经授权不得进交付物。

## 五、素材库的五步用法

1. **先有词，再去看**。从概念主张里取三组词（基调 / 材质 / 排除项），带着词去检索；
   漫无目的地刷会把方向带偏，也拉不出可复用的结论。
2. **只看关系，不看具体户型**。关注构图重心、材质冷暖对比、光从哪来、留白多少；
   不关注"这个客厅多大、这面墙多长"——那些要回到已确认模型。
3. **提取可验证特征**。写成可判定的句子，例如"深色石材到顶、木饰面只做腰线以下 900mm"；
   不写"高级""有质感"这类无法核对的形容词。
4. **落成词与比例**。把结论写进 `keywords.json`：基调词、材质词、排除词，以及冷暖占比、
   黑色占比这类可量化口径（判据见 `skills/moodboard-aesthetic-iteration.md`）。
5. **记来源**。在 `reference-log.md` 里逐条登记：参考对象 → 来源 → 提取到的特征 → 用在哪一处。
   登记的是**结论的出处**，不是图的副本。

## 六、专业案例研究的六条规矩

案例研究是 S1 的一部分，不是新阶段：客户刚说完"三层极简别墅"，就该看到真正的建成案例，
**不等所有问题问完，也不等 G1 签署**。

1. **唯一首选入口是 Luxora AI**。其余来源都是补充，补充只在"真的能读到"时才写进清单。
2. **每次 5–8 个，不堆几十个**。凑数比少给更有害：业主会以为你都看过了。
3. **每个案例必须能被打开**。标「已回读核验」的，是生成时真的打开过页面并核对了标题；
   打不开的降级为「未核验」，并写明原因。
4. **记录的字段固定**：案例名与设计师/事务所、专业类型、来源与真实链接、可打开的实景图链接、
   与业主哪些诉求相符、值得借鉴的手法、不适合照搬的地方、核验状态与图片权利。
5. **图只给链接，永不嵌入**。第三方作品的图像权利属原作者与摄影师，公开可见不等于授权复制。
   只有自有内容、已授权内容、本系统产出的图可以进 PPT 或意向板。
6. **读不到就说读不到**。网站无法访问、没有检索权限、图片不可核实，一律写明情况。
   **绝不编造项目、图片、链接。** 一个说清原因的空清单，胜过一个漂亮但不存在的案例。

案例成果落在 S1 输出目录的两份文件里：`reference-shortlist.md`（客户看）与
`reference-shortlist.json`（S2 读）。它们不是第二套案例库——结构化数据只有这一份，
人读版本与它同源。

## 六之二、案例怎么进到客户眼前（S2 接线）

清单是给客户看的，但客户最终看的是**方案与提案**。所以案例必须进到这两个地方，
否则等于只存在数据库里。

| 落点 | 位置 | 呈现方式 |
|---|---|---|
| 意向板第七格 | `concept/moodboard.py` `CASE_SLOT`「⑦ 参考案例」 | 项目名 + 事务所 + 链接 + 一句话转化；**不嵌图** |
| 提案案例页 | `concept/deck.py` `_reference_slide()` | 每套方案一页，四问 + 链接表 |
| S2 选项文档 | `concept/references.py` `markdown()` | 每套方案的案例与四问全文 |

**挑选只做一次**：`concept/__init__.py` 在生成意向板之前算好案例，意向板与提案共用
同一份结果。若两处各挑一次，同一套方案会出现两个不同的参考案例，客户无从判断。

挑选判据有两条，且顺序固定：

1. **风格与感受分**（`_score`）——概念自己的风格词、感受词是否命中案例文本。
   中文词经 `TERM_BRIDGE` 换成案例文本可能用的英文说法；未收录的词就是不匹配，
   **不匹配不构成证据**。
2. **空间家族分**（`_family_bonus`）——只在风格分差 ≤ `FAMILY_TIE_WINDOW` 时才有
   裁决权。业主指定风格时三套概念风格分常常只差一两分，若让这点分决定排序，
   三套会挂同一个案例。家族词是**平局裁决，不是加分项**；案例文本不支持某个家族时
   返回 0，不猜。

所以三套概念挂同一个案例，可能是真结果：如果真实案例文本里没有能区分它们的证据，
就不硬拆。**空着或共用，都比编一个差异好。**

## 七、与能力的关系

| 能力 | 怎么用这份规范 |
|---|---|
| `moodboard-aesthetic-iteration` | 主入口：调研 → 关键词 → 打分 → 意向板（意向板图像须自有或授权） |
| `concept-design` | 用调研结论收敛概念方向，不用参考图替代概念主张 |
| `material-design` | 参考材质搭配的**关系**，具体材料型号与性能须另查手册与检测报告 |
| `design-presentation` | 汇报里引用调研结论时注明"方向参考"，不附原图 |
| `concept-design`（S2 挂案例） | 每套概念附 1–2 个案例，回答：为什么参考 / 借鉴什么 / 怎么转化 / 什么不能照搬 |

## 八、红线

1. 不得把素材库的图下载后放进意向板、汇报 PPTX、效果图或任何交付文件。
2. 不得把素材库的图当作材料样板、工艺依据或采购参照——图上的材质未必是真实材料。
3. 不得声明"行业标准如此""主流做法都是这样"——素材库是流行趋势的样本，不是标准来源。
4. 不得从参考图反推尺寸、面积、构造做法；几何只认已确认模型。
5. 不得把聚合站点自身的界面、水印、标识截进交付物。
6. 用户提供的参考图，若未明确可复用，按调研级处理。
7. 不得把读不到的站点写成"已检索"，不得用虚构条目填充清单。
8. 案例照片不得冒充本项目的效果图；需要看本项目的效果图时走原创生成，两者不混放。

## 九、常见错误

| 错误做法 | 后果 | 正确做法 |
|---|---|---|
| 把素材库截图贴进意向板 | 版权风险，且业主会误以为是本方案 | 只写结论：材质、比例、明暗关系 |
| 参考图当尺寸依据 | 几何与已确认模型冲突 | 几何只认统一空间模型 |
| 只存图不记来源 | 后续无法追溯结论从哪来 | 逐条登记 `reference-log.md` |
| 用参考图证明"大家都这么做" | 把趋势当标准 | 判据回到 `knowledge/` 与规范原文 |
| 拿参考图直接当提示词喂给平台 | 生成结果与已确认平面对不上 | 提示词写空间与材质，几何由模型锁定 |
| 用材料网站当案例来源 | 得到一堆产品图，看不到空间 | 案例站做研究，材料站选材，分开用 |
| 案例数量堆到二十个 | 业主无法比较，等于没给 | 精选 5–8 个，每个说清借鉴与不借鉴 |
| 网站读不到就编两个项目 | 业主点开是 404，信任一次归零 | 写「读不到」，并给出人工入口与检索词 |
