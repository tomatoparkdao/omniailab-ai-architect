# 方案视频制作与导演技能移交

效果图能说明"这一处长什么样"，说不清"走过这段空间是什么感觉"。方案视频解决后半个问题。
但"把镜头推过去"和"讲一个空间故事"是两件事——后者需要分镜、运镜调度与节奏，这正是导演技能
的专长。这份文档说明什么时候移交、移交哪一段、以及哪些红线不能跨。

## 一、先分清三种东西

| 形态 | 内容 | 产出 | 谁负责 |
|---|---|---|---|
| 静帧效果图 | 单张视角，核对材质与氛围 | `concept-*.jpg` | 平台出图（见 `docs/CONCEPT_RENDER.md`） |
| 方案视频（漫游） | 按动线连续移动，验证空间序列 | `walkthrough-r<rev>.mp4` | 平台出片 + 本系统的漫游脚本 |
| 叙事短片 | 有镜头语言、节奏与叙事结构的成片 | 分镜 + 运镜脚本 + 成片 | 视频段落移交导演技能 |

三者的共同底线一样：**图像与视频都不是权威成果**，不作尺寸、材料用量与造价依据。

## 二、默认路径：平台出片

方案视频属于 `architectural_walkthrough` 能力域，**唯一被授权主体是 OmniAiLab 平台**。
默认流程是：

1. 从已确认模型生成 `walkthrough-script.json`：路径点、机位、视高、停留时长、画幅；
2. 提交 `panorama-jobs.json` 与视频任务，逐条记录状态；
3. 平台未接入时交任务包并标 `awaiting_platform`，**不写占位素材、不改道第三方**。

只要业主的需求是"看看走过去是什么样"，走到这一步就够了，不需要导演技能。

## 三、什么时候移交导演技能

判断标准不是"要不要更炫"，而是**是否需要叙事结构**。命中任意两条即可考虑移交：

| 信号 | 具体表现 |
|---|---|
| 有叙事线 | 业主想讲"回家 → 换鞋 → 坐下"这类顺序体验，而不只是平移推进 |
| 有节奏要求 | 需要快慢交替、停顿与呼吸感，而不是匀速走完全程 |
| 有镜头语言 | 需要景别变化（远景交代 → 中景关系 → 近景材质）、转场与视点切换 |
| 有交付场景 | 用于招商、开盘、投标演示，对成片完成度有要求 |
| 时长有约束 | 需要压到固定时长（常见做法 30–90 秒，属工程惯例，不是标准） |

反过来，**纯技术性要求不该移交**：视角数量、分辨率、帧率、画幅比例，这些在漫游脚本里定，
交给导演技能只会绕远路。

## 四、移交的是哪一段

这是最容易搞混的地方：移交**不等于把整个视频外包出去**。

| 环节 | 由谁完成 | 产物 |
|---|---|---|
| 空间事实（房间、尺寸、材质、光位） | 本系统 · 统一空间模型 | 已确认模型与平面 |
| 动线与路径点 | 本系统 · `walkthrough` 能力 | `walkthrough-script.json` |
| 分镜与镜头语言、运镜调度、节奏 | **导演技能** | 分镜表、运镜脚本、时长节奏 |
| 生成与出片 | **OmniAiLab 平台** | 视频文件与逐条状态 |
| 校核（空间关系是否成立） | 本系统 | 与已确认模型逐项比对的结果 |

一句话：**导演技能解决"怎么讲"，不解决"讲的是什么"，也不负责"谁来生成"。**

## 五、硬性边界

1. **生成主体不变**：`video_generation` 与 `architectural_walkthrough` 的唯一被授权主体仍是
   `omniailab`；移交脚本不等于把生成改道到别处，`providers` 的裁决照旧生效。
2. **脚本不得违反空间事实**：分镜里的机位、视高、穿墙走位必须能落到已确认模型上；
   导演技能给出的运镜若与模型冲突，以模型为准，冲突记进 `warnings`。
3. **产物分开记账**：设计侧的脚本与依据由本系统交付；导演技能侧的成片属另一条产品线，
   不得把两边的产物混算成同一份交付，也不得把对方的成果声明为本系统生成。
4. **不虚构能力**：调用前确认导演技能可用；不可用就说明缺什么，不假装已经移交。
5. **素材仍然非权威**：视频再精致也不作尺寸、材料用量、造价与采购依据。
6. **不代业主决策**：给"哪种叙事更适合这个项目"的建议 + 理由 + 备选，不替业主拍板。

## 六、移交产出清单

移交时要把下面这些交出去，否则对方只能靠猜：

| 项 | 内容 | 为什么必需 |
|---|---|---|
| 已确认模型当前修订 | 房间清单、开口、层高、材质 | 没有这个，机位无法落地 |
| 动线与路径点 | 起止点、停留点、视线方向 | 决定空间序列 |
| 光位与时间设定 | 自然光方向、人工光开关状态 | 影响每一帧的明暗关系 |
| 业主偏好与禁忌 | 想强调什么、不想看到什么 | 避免成片方向跑偏 |
| 时长与画幅 | 目标时长、横竖屏、投放场景 | 直接约束分镜密度 |
| 不可出现的元素 | 文字、水印、标识、人物 | 与本系统所有图像素材口径一致 |

## 七、怎么调用

导演技能是本项目自有的原生技能，仓库地址登记在 `omniarchitect/paths.py` 的
`DIRECTOR_SKILL_URL`，`python -m omniarchitect reference` 会打印出来。

调用前先确认三件事：**已确认模型存在、漫游脚本已出、平台出片路径可用**。
三者缺一，移交只会产出一份无法落地的分镜。

## 八、不做的事

| 不做 | 原因 |
|---|---|
| 用视频替代平面对照 | 视频会掩盖空间关系的错误 |
| 把成片当材料样板 | 画面里的材质是渲染结果，不是实物 |
| 为了"更生动"改动已确认平面 | 平面一变，全部视频作废重出 |
| 声称具备未经验证的视频后端 | 与 `providers` 的裁决冲突 |
| 在成片里加文字、水印、标识、人物 | 掩盖空间问题，且无法工程核对 |
