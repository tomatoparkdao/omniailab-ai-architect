# 概念汇报：先让客户看到好设计

这一页回答一件事：S2 结束的时候，客户手里拿到的是什么。

不是一份二十多页的文字提案，也不是一排参考链接，而是一份**事务所式的概念汇报**：
八到十二页，图是主角，每页只讲一件事，最后给一个明确的推荐和下一步。

## 一页判断、一版汇报、一份动画

| 产物 | 位置 | 作用 |
|---|---|---|
| `design-position.md` | S1 | 一页讲清项目性质、功能重点、审美方向、限制、待确认问题（≤3 个） |
| `concept-proposal.html` | S2 | 客户版汇报，浏览器翻页，可打印成 PDF |
| `concept-proposal.pptx` | S2 | 同一份页面模型渲染的可编辑 PPTX，文字是真文本框、图是真图片 |
| `concept-motion.html` | S2 | 体块演变动画，离线可播，可暂停/重播/逐帧 |
| `concept-proposal.md` | S2 | 逐页文字稿，供检索与留档 |
| `concept-options.md` | S2 | 完整专业资料（面积、参数、案例、取舍），当附录用 |

HTML 与 PPTX **不是两份内容**：它们都从 `proposal.build()` 产出的页面模型渲染。
改版面只改一处，两边同时变；页数测试守着这一条。

## 页面顺序

| 页 | 讲什么 | 图 |
|---|---|---|
| 01 封面 | 项目名、概念主张 | 素材库同级实景（有）／自有图版（无） |
| 02 设计定位 | 性质、功能重点、审美、限制 | 一张意向图（可选） |
| 03 参考意向 | 为什么是这几张、借什么、不借什么 | 3 张真实参考，带出处 |
| 03b 对标案例 | 同类建成项目怎么做、我们借哪一手 | 三张案例卡片（只有文字与链接） |
| 04 主推方向 | 概念名 + 一句主张 | 自有图版，整幅（建筑体块／室内标准层／景观总平面） |
| 05 设计回应 | 功能／空间／体验各一句 | 无图，纯排版 |
| 06 概念推敲 | 这套方案凭什么成立 | 四步推演图，**按专业画**（见下一节） |
| 07 备选方向 | 另一套组织逻辑 + 代价 | 备选图版 |
| 08 材料与光 | 色板、主材、光、配色比例 | 色块 + 材质细部 |
| 09 建议 | 推荐哪套、为什么、G2 确认什么 | 无图 |
| 10 附录 | 面积、参数来源、未决事项、免责 | 无图 |

页数随内容浮动，不硬凑：设计机会不足两条时**这一页不出**（把功能并进定位页），
所以简单项目落在 8 页，复杂公共建筑最多 12 页（`page_cap`）。技术校核不进主线，
逐条文字版 `concept-presentation.pptx` 降为附录留档，不当作给客户的那一份。

## 图版分专业：客户看到的是他委托的那件事

同一个 `plate.py`，按专业出三种图，**并且按版面像素尺寸现画**：

| 专业 | 图版 | 画什么 | 不画什么 |
|---|---|---|---|
| 建筑 | `hero_plate` | 等距体块、院子、入口、指北、比例条 | 内部家具与尺寸 |
| 室内 | `plan_plate(interior)` | 标准层：客房带／走廊／公共核／后场，入口箭头 | 场地与体块 |
| 景观 | `plan_plate(landscape)` | 总平面：建筑边界、水面、环路、种植、节点、主入口 | 体块轴测 |

两条硬规则：

1. **尺寸对得上**。图里的字是固定 px，1280×560 的图缩到 800×452 放，11.5 px 的标注
   就变 7 px——所以封面按 800×452 出、主推页按 1200×496 出、备选按 940×448 出。
2. **委托范围对得上**。景观项目的封面不接受建筑外立面照（`_is_landscape_shot`），
   宁可换成自家画的景观总平面——拿房子当院子的封面，客户一眼就知道你没看懂委托。

## 概念推敲：按专业推，不套同一套动画

`concept/evolution.py` 从概念自己的数据（分区、序列、采光、主张）推出四步，
专业决定"推敲什么"，而不是所有项目都演一遍体块加法：

| 专业 | 四步 | 图画什么 |
|---|---|---|
| 建筑 | 场地与限界 → 体量分解 → 加入要素 → 结果形态 | 等距体块逐步叠加 |
| 室内 | 功能重组 → 空间序列 → 界面与通透 → 核心空间 | 平面图逐步显形：分区 → 客流 → 开窗 → 核 |
| 景观 | 场地与边界 → 空间层次 → 园路与节点 → **按方案命名** | 总平面逐步显形：场地 → 种植 → 游线 → 节点 |

景观第四步不写死：静水写「水景与种植」、旱溪写「旱溪与种植」、林下写「林下与茶席」
（`evolution.LANDSCAPE_LAST_STEP`，键是 `layout.landscape_kind()` 判出来的方案类型）。
三个方向共用一个"水景与种植"，等于图上没水、标题还在说水。

三条约束：

1. **推不出来就不画**。概念里没有分区/序列/采光时，`plan()` 返回 `ok=False` 并说明
   缺什么；提案改出「这套方案凭什么成立」的文字页（四条判断全部来自策略字段），
   `anim.build()` 返回 `skipped`，**不生成动画**。宁可少一个动画，不放不相干的推演。
2. **步骤不复读**。四步的说明按顺序取不同字段，同一句话不会出现两次。
3. **四步不移动已经定下来的东西**。四步与主推图读的是 `concept/layout.py` 的同一份
   几何，只是按 `appear` 逐项显形、按 `emphasis` 点亮；客厅、走廊、茶座的位置
   从头到尾一个坐标。改几何只改一处。

`concept-motion.html` 的动画与提案里的四步图同源（同一套 `scenes()`），
标题随专业变（MASSING／SEQUENCE／SITE），不是换个项目名接着播。

## 图版几何：一份数据，两处渲染

`concept/layout.py` 是室内与景观图版的**唯一几何来源**：区域是归一化矩形，
节点是归一化点，联系是折线。`plate.plan_plate()` 画主推图，`evolution` 画四步，
两者调同一个 `draw()`。v1.15 之前是两套百分比坐标，同一个"公共核"在两张图上
位置不同，最后一步还会挪一下——客户把两页并排看就露了。

怎么定画什么，读概念已经声明的字段，不新设分类：

| 专业 | 判据 | 结果 |
|---|---|---|
| 室内 | `spatial_prototype.plan_layout` | `public_core` → 两幅（裙房公共层／客房标准层）；`guest_wing` → 一幅标准层；`tech_core`／`cluster_atrium`／`process_line`… → 各自的三段式 |
| 室内（住宅策略） | `spatial_prototype.massing_kind` | `spine` → 一条服务脊；`loop` → 中心体块回游；`darklight` → 明暗两段；`inner_box` → 盒中之盒 |
| 室内（无声明） | 委托类型 + `family` | 按类型给中性分区（住宅＝公共区／通道／私密区），按家族换形状（线性／组团／环形），图注写明"功能关系示意" |
| 景观 | `spatial_prototype.massing_kind` | `pond` → 一池静水；`terraces` → 旱溪台地；`grove` → 林下茶席 |

### 没有声明平面组织方式时

`plan_layout` 只有行业方向（教育、医疗、工业、酒店、景观）才填。普通家装与办公本来
就没有——**这时绝不能退回某个行业的模板**：拿"教学／专用教室"去标一间住宅，是客户
一眼就能看穿的错误。所以：

* 只从类型表取中性分区（`NEUTRAL_BANDS`），不写客户没提过的房间；
* 三个方向若都画同一张图，客户会问"这不都一样吗"，因此按概念已声明的 `family`
  换组织形状（线性三段带／组团四点块／环形中心核）；
* 图注如实写「概念未声明平面组织方式：本图为功能关系示意，不是排房图」；
* 不用 `experience_sequence` 当标签——那串字是给人读的（"右手是接待台"），
  抽出来当图注只会出洋相。

非酒店项目即使命中 `public_core`，也只画公共层：**不当心带出客房标准层**。
判断是不是酒店看 `sector` 与概念里的用词（`_is_hotel`），认不出来就写明"只画公共层"。

四条硬规则：

1. **公共层与标准层分开画**。`public_core` 的酒店一定出两幅：公共核（大堂／餐厅／
   会议／前台／客梯厅／后场）在裙房，标准层只有客房／走廊／客梯厅／服务核。
   把大堂画进客房层，就是"把公共核画成走廊边上的一个房间"。
2. **没有水面就不画水**。`massing_kind=terraces` 的方案主张是"不做池子"，
   图里连水色都不能出现（测试守 `#DDE7EE` 不出现）。旱溪画成砾石带。
3. **房子是场地条件**。主推与备选共用同一块建筑轮廓，换方案不换房子。
4. **关系要闭合**。入口到环路必须接通（`test_entry_path_touches_the_ring`），
   园路不许穿水面，茶座在入口的对面岸、视线穿过水面才看得到倒影。

### 标注怎么摆

标签位置由图形几何算出来，不是按百分比贴：

* 放得下就放区域内（左上、居中）；椭圆区域（水面）居中，因为 bbox 的角不在水面上；
* 放不下就引到外侧，引线只连最近的边，避开别的区域与水平流线；
* 标签互不重叠、不出界（`test_labels_stay_in_the_frame_and_never_overlap`）；
* 图上只留 2–6 个字的短标签，长句交给页面正文。

**重要标签不许因为"放不下"就消失。** 入口、公共核、大堂、后场、水景、茶座是读图的
锚点，丢了这张图就白画了。所以 `draw()` 这样做：

| 环节 | 做法 |
|---|---|
| 排序 | `Frame.keep` 里的先排，普通区域其次，乔木等装饰标签最后 |
| 放宽 | 先找不压任何区域的位置 → 允许压过区域改用引线 → 字号降到 0.86 倍 |
| 换位 | 嵌套区域（盒子／盒外、茶席／草坪）不把外层当障碍；点标签允许落在房里；入口标签可落进左侧留白 |
| 留痕 | 三层都放不下，写进 `report["missing"]`，由页脚印「未放置标注：…」 |

字号只降一档：再小就不是标注、是墨点，客户在 16:9 页面上读不到。

### 图与话必须是一件事

概念主张、`massing_kind`、图版三者不许打架。`layout.landscape_kind()` 以声明为准，
但**文字能否定图形**：原型写着 `pond`、主张却写"不做池子"，就按无水方案画，并把矛盾
写进图注（`layout.consistency()`），等数据修正——不能一边写"一池静水"，一边画无水
旱溪，只因图上没画水池就算通过。反过来，主张提水、原型是无水做法时也照原样标出来。

## 对标案例：素材库没有，就去真实项目里找

素材库（Luxora AI）优先。没有同类实景时不停在这里，走 `research/cases.py` 的
真实检索：按**项目类型**选分类页（A3→教育建筑、A4→医疗、A12→工业、B6→餐饮…），
而不是按专业选——这一层以前只有专业，小学被归进 houses，案例页上全是别墅。

| 环节 | 规则 |
|---|---|
| 分类页 | `ASPECT_PAGES`，每个 slug 实测可打开（200 + 24 条可解析） |
| 打分 | 类型词是信号（school/campus/factory…），不是噪声；别墅在学区项目里扣分 |
| 核验 | 详情页回读成功才标「已核验」，标题不一致标「部分核验」，打不开标「未核验」 |
| 图片 | 第三方照片只给链接（`image_rights=link_only`），不嵌进可再分发的 PPTX |
| 四问 | 为什么 / 借什么 / 不照搬，全部取自该案例自己的标题与简介，两条案例不共用一段话 |

## 风格怎么选：先认项目类型，再看客户原话

`style/recommender.py` 先按**空间用途**收窄候选池（项目类型 → 用途：A3→教育、A4→医疗、
A12→工业、B4→酒店、C2→庭院），声明不足三条时用同族补足；同分按该用途的常用族排序，
不再按 style_id 字母序。`concept/directions.py` 把类型代码翻成用途词去提问，
`concept/quick.py` 再给一份类型短名单供 S1 页参考。

否则会出现 v1.13 的问题：24 班小学被推荐"非洲当代／美式古典／装饰艺术"——
因为所有风格同分，字母序第一个（`african-contemporary`）永远是"稳妥方案"。


## 图的三类，版面必须分开

| 类型 | 来源 | 标注 | 能不能当尺寸依据 |
|---|---|---|---|
| 参考照片 | 自有素材库（第三方摄影） | `参考 · 出处` | 不能 |
| 自有图解 | `concept/plate.py`、`concept/diagrams.py` | `自有图解 · 非按比例` | 不能，但空间关系可被指认 |
| 概念意象 | 平台生成（需授权） | `平台状态 + 已生成/待平台` | 不能 |

未配置平台时**不放替代图**，只在附录写状态。这条在 v1.8 定过，本轮沿用。

## 参考怎么选

1. 从客户原话里取感受词（`MOOD_WORDS`）、已选风格、任务书房间名，形成检索条件；
2. 在已建索引 `knowledge/library/catalog.json` 里按专业与用途匹配，取 3–5 张；
3. 每张给四个答案：为什么适合、解决什么问题、借什么、什么不能照搬；
4. 用途不匹配就**不取图**并说明原因（学校、医院、厂房在现有索引里没有实景）；
5. 结果写进 `assets/curation.json`，同一修订号复用，不重复下载。

权限口径：素材库图片可用于**本项目提案**并注明出处；公开宣传或再分发前须另清权。
第三方建成项目案例只给链接，不嵌图。

## 主图版为什么自己画

现有分析图是 A4 式的：信息全、字小，缩到 16:9 页面就不可读。客户在概念阶段要看的
是一张**大图**——体块怎么落在场地上、院子在哪、入口从哪进。

`concept/plate.py` 因此只画三件事：一个体块、三条大字标注、一个入口。五种空间家族
（线性／分层／组团／围合／中庭大厅）各一套组合，颜色跟着 `视觉.md` 走。它仍然是
矢量、确定性绘制，不碰生成式图像。

分析图（1280×720、自带标题图例的那种）**不再进客户页**：缩到 500 px 宽只剩一团灰，
不如把三条判断排清楚。它仍保留在 `concept-diagrams/` 供专业阅读。

## 动画：先讲清因果，再谈氛围

`concept-motion.html` 用四步讲体块：占满可退界 → 断成两段 → 切出缺口 → 连桥与入口。
每一步只改一件事，客户才看得懂"为什么长这样"。

它不是视频，也不是效果图：页脚写明"体块关系示意，不作尺寸依据"。需要生成式氛围
短片时，仍走 `providers/canvas.py` 的授权链路；平台未配置时给分镜与任务包，不伪造文件。

## 速度：不重复做同一件事

| 容易重复的地方 | 现在怎么做 |
|---|---|
| 客户已答的问题 | `interview.next_questions` 只问没答过的槽位，每轮 ≤3 |
| 参考图 | `assets/curation.json` 按「项目 + 修订 + 风格」缓存，图片本体按 URL 缓存 |
| 同一张图渲染两次 | 封面图与主推图各按自己的尺寸出一次，不再缩放复用 |
| 图解转 PNG | `assets/_png/` 缓存，按文件名判重 |
| 汇报与提案 | 同一份页面模型出 HTML/PPTX/MD，不各写一遍 |
| 全量技术校核 | 概念阶段不做；校核在 S3 与 G3 |

快不等于糙：功能判断、概念创意、审美品质这三条不能省。

## 文字纪律

客户页面上不该出现的东西，代码里直接挡住：

| 问题 | 处理 |
|---|---|
| 半句话（"组团之间用一个共享中庭串起来，食堂 356 m² 与体…"） | `_clip` 先按 `。；，、` 断句，断不开才用省略号 |
| 内部字段（`parti:`、`zoning:`） | `_clean_strategy` 去前缀 |
| 内部流程（"G1: 已确认（业主）"） | 客户页不写门禁状态，只写设计结论 |
| 空标签（"配色比例"后面什么都没有） | 没有正文的块不画；配色比例只取色板声明值，没有就直说 |
| 图注与标题重复 | 图版 `heading=False/footer=False`，标题由页面排 |

## 验收

三个项目（公共建筑／室内／景观）各从一句客户需求开始，走真实 S1→G1→S2，
产物与截图见 `docs/ACCEPTANCE_ROUND6.md` 与 `out/concept-round/`。
