# 设计判据体系

本文件说明 **OmniArchitect 用哪些判据做设计判断**，以及每组判据落在哪个阶段、由哪项能力执行。

判据是本系统的**自有工作口径**，来源为通用设计原理与公开工程惯例，全部由本项目独立撰写，
不使用、不复制、不改写任何第三方文档。程序可读的同一份数据在
`omniarchitect/registry.py: DESIGN_CRITERIA`，可用
`python -m omniarchitect criteria` 打印。

---

## 一、为什么要单独有一份判据表

设计方案的分歧几乎从不出现在"会不会画"，而出现在"凭什么这么定"。所以本系统把判断拆成两层：

- **阶段**负责推进节奏（什么时候必须停下来确认）；
- **能力**负责专业方法（这件事按什么标准做）；
- **判据**负责给出可判定的依据（为什么这么做，以及什么情况下算不成立）。

判据必须**可判定**——写成"要高级""要有质感"是没有用的，要写成"暖材占比 ≤40%""黑占比 3–8%""全场只留一条主导线"这类能被人和程序同时检查的句子。

## 二、九组判据

### 1. 美学控制基线（`aesthetic-restraint`）

- 参与阶段：S2 概念方案、S3 平面方案、S4 初步设计
- 执行能力：`concept-design`、`space-planning`、`interior-design`、`material-design`

| 判据 | 可判定的形式 |
|---|---|
| 冷暖对峙 | 冷调打底、暖色点睛，暖材占比 ≤40% |
| 一条主导线 | 全场只保留一条主导线；天花是第一叙事面 |
| 黑作重音 | 黑色占比 3–8%，作重音不作块面 |
| 纹理分密度 | 同一纹理至少给出三种密度，避免整面同质 |
| 光要有落点 | 每个标高至少一处发光的面 |
| 概念四步 | 锚 → 象 → 法 → 形，缺一步概念不成立 |
| 平面四问 | 好采光面是否被独立房间独占 / 客户流线是否穿过私密区 / 平面上是否有真实主导线 / 是否留出一个"空的地方" |
| 配色校验 | 60-30-10 配比 + 黑色 5% 的独立校验 |

> 判据不成立时，必须在方案对比里写出来，不许静默调参。

### 2. 概念图解语言（`concept-diagram-language`）

- 参与阶段：S2、S4、S7
- 执行能力：`create-draw`、`concept-design`、`construction-detailing`

- **批注色彩语义**：红=问题与张力、蓝=方向动线与视线、橙=光的动作、绿=亮点、灰=参考；
- **概念图解三段式**：概念主张 + 空间原型 + 光/材质/动线三策略；
- **图主文辅**：图上标签 ≤12 字，说明栏每条 ≤30 字。

### 3. 意向板迭代闭环（`moodboard-iteration`）

- 参与阶段：S2、S5
- 执行能力：`moodboard-aesthetic-iteration`、`scene-rendering`

- 流程：意向板 → 关键词三组 → 量化打分 → 跨轮整改追踪；
- 诊断维度：200ms 第一印象、Design Critic 六维、60-30-10 拆色；
- **口径固定**：同一项目内评分体系不得中途更换，否则跨轮分数不可比。

### 4. 机电对空间的影响（`building-services-impact`）

- 参与阶段：S4、S6、S7
- 执行能力：`building-services`、`coordination-check`

- 暖通 / 给排水 / 电气 / 竖向交通 / 消防对空间的影响速查；
- 机房、管井、净高与吊顶空间占用的判断口径。

> 本组只做**空间影响判断**。具体系统设计、负荷计算与当地规范符合性由持证专业人员完成。

### 5. 批注台账（`annotation-ledger`）

- 参与阶段：S6、S7、S8
- 执行能力：`delivery`、`design-review`

- 逐条核销：每一轮意见进入台账，跨轮可追踪、可核销；
- 交付形式：成果主文件 + 意见 → 批注版交付物。

### 6. 提案版式（`proposal-layout`）

- 参与阶段：S8
- 执行能力：`documentation`、`design-presentation`

- A3 横版提案的网格版式与交付文本规范；
- 汇报必含边界页（免责与待专业复核项），否则不得提交。

### 7. 项目适配判断（`project-fit`）

- 参与阶段：S1
- 执行能力：`design-brief`

- 能力边界与造价档位匹配：项目该不该接、能不能做；
- 只参与 S1 的可行性判断，不参与设计生成。

### 8. 量价分离（`cost-separation`）

- 参与阶段：S1、S8
- 执行能力：`cost-check`、`quantity-takeoff`

- 工程量与单价分开记录，便于逐项校准；
- S1 起动态估算，S8 形成正式清单——口径一致才可比。

### 9. 工具安全分级（`tool-safety-tiers`）

- 参与阶段：—（贯穿全部阶段的服务性判据）
- 执行能力：—（作用于适配器与审核门槛）

- L1 只读 / L2 本地写 / L3 联网 / L4 执行发送；
- L3 需授权，L4 需先 dry-run；未授权即拒绝执行。

## 三、判据之间冲突怎么判

1. **平面优先于表现**：平面四问不通过时，效果图再好看也不算成立；
2. **人体工学优先于造型**：净宽、进深、通行宽度不足时，造型让步；
3. **规范与安全优先于一切**：涉及结构、消防、无障碍、负荷时，本系统只标注问题，不下结论；
4. **业主确认优先于内部审美**：功能需求未确认前，不进入精细建模。

---

## 四、判据如何被检查

- `python -m omniarchitect criteria` —— 打印判据表；
- 概念、平面、初步设计、表现四个阶段的门禁前，判据会被逐条检查并写进该阶段的评审段落；
- 检查未通过的条目进入 `warnings`，并如实出现在交付文件与汇报的"待确认事项"里。

---

## 五、边界

- 判据是**工作口径**，不是法规；项目所在地的强制要求优先于任何一条判据；
- 判据不覆盖结构安全、消防、无障碍与机电负荷的最终结论；
- 判据可被业主的明确要求覆盖，但覆盖必须被记录，不能悄悄发生。
