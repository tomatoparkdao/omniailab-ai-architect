# 设计意图执行层闭环

## 一、这一轮修的是什么

上一轮能**识别**"这条改动触及已确认的设计意图"，但识别之后仍然照改。等于自己提醒
自己，然后自己无视。本轮把"提醒"变成"改不动"。

| 漏洞 | 后果 | 现在的行为 |
|---|---|---|
| `analyse(apply=True)` 识别出 requires_formal 仍执行 | 保护机制形同虚设 | 无有效授权即拒绝执行，项目一个字不改 |
| `apply_change(apply=False)` 仍 `invalidate_from` + `_persist` | 预览一下就把项目变成返工状态 | 预览全程只读，连修订号都不动 |
| S1 面积冲突与 S2 硬门槛分类不对齐 | 同一问题在 S1 报警、S2 变通过 | 统一 `hardgate`，一套维度一套状态 |
| G2 事务浅拷贝 + 文件快照缺意图 | 回滚后残留半改数据、孤立基准 | 深拷贝 + 四类文件字节快照 |
| G2 只信 S2 排名 | 排名漏判则门禁一起漏判 | G2 独立复核硬门槛 |

## 二、两阶段变更

### 阶段 A：提出（`changes.propose`）

只分析、只出提案，**不碰项目数据**。提案包含：改动落点、受影响的专业与阶段、
是否触及受保护特征、要谁批。

```python
req = changes.propose(project, "把客厅和餐厅之间的墙打掉")
# req.request_id / req.approval_scope / req.requires_authorization
```

写盘时文件名为 `change-<stamp>-proposal.json`，且 `applied=false`——报告不能
伪装成已执行记录。

### 阶段 B：确认后执行

```python
auth = changes.authorize_change(req, by="业主张先生", note="确认打通")
rep = changes.apply_change(project, req, authorization=auth)
```

授权被四条绑定：

| 绑定 | 失效条件 |
|---|---|
| 请求 ID | 授权对应的不是这份变更 |
| 项目修订 | 项目已从 r1 走到 r2 |
| 设计意图 ID | 意图基准被换掉 |
| 意图内容摘要 | 特征原文被改过 |

外加两条硬要求：`source=owner`（演示、脚本、`--force` 一律拒绝）、必须有署名。

### 谁能绕过

谁都不能。`--force`、`apply=True`、脚本代理、演示批准都不在授权路径上——
它们连生成授权指纹的机会都没有。低风险调整（换颜色、同档材料）不需要授权，
但那一类改动本来就不会动空间关系。

## 三、统一硬门槛

`omniarchitect/hardgate.py` 是唯一的判定处，S1 摘要、S2 排序、G2 确认都调它。

### 五个硬维度

| 维度 | 问题 | 来源 |
|---|---|---|
| area | 客户说的面积与模型实测是否对得上 | 可行性检查 |
| capacity | 这些人、这些功能装不装得下 | 可行性检查 |
| safety | 是否存在经验证的安全问题 | 可行性 + 不确定登记 |
| regulation | 是否违反已确认的强制性规范 | 可行性 |
| physics | 净高、坡度、排水、检修空间是否成立 | 可行性 + 专业缺口 |

### 四态语义

| 状态 | 含义 | 能不能推进 |
|---|---|---|
| `failed` | 已有证据证明不成立 | **不能**，美学分不能抵消 |
| `unknown` | 缺资料，尚未确定 | 能作为方向，不能当结论 |
| `passed` | 当前深度已通过检查 | 能（不等于已通过专业计算） |
| `not_applicable` | 范围判定不涉及 | 不涉及 |

三条铁律：`unknown` 不等于 `passed`；`failed` 不能加权；同一维度多条结论
按"最坏者胜"（failed > unknown > passed）。最后一条是修 bug 修的：
一条 `info`（"面积有余量"）曾把 `major`（"面积口径不一致"）盖掉。

### 全被拒时

所有候选概念的硬门槛都 failed 时：

- 排序里全部 `rankable=false`，排在可行方案之后；
- 推荐意见写"这不是选哪个方案的问题，是这个项目现在不成立"；
- G2 独立复核出 `G2-HARD-<维度>` 阻断，签不了。

## 四、G2 事务：字节级回滚

快照四样东西：

| 对象 | 方式 |
|---|---|
| 概念状态（options/concepts/baseline） | `copy.deepcopy` |
| S2 阶段状态 | `copy.deepcopy` |
| `design_intent` 与 `leadership` | `copy.deepcopy` |
| 风格锁 / 交接 / 多专业基准 / 意图文件 | 按字节保存 |

浅拷贝的问题不是理论问题：`state.update()` 拿回来的嵌套对象仍是被改过的那份，
回滚"看起来成功"，实际留着半改数据。

回滚规则：原本存在的按原字节写回，原本不存在的删除。所以**不会**误删上一版
已批准的意图文件，也不会留下没有门禁背书的孤立基准。

## 五、G3–G8 漂移检测

`omniarchitect/conformance.py`，每个门禁前跑一次，结果落 `meta.conformance[stage]`。

### 三种结论

| 结论 | 判据 | 门禁行为 |
|---|---|---|
| `passed` | 结构化比对通过 | 放行（不代表美学判断通过） |
| `changed_requires_approval` | 已可证明改变 | **拒绝确认**，要求变更审批 |
| `unknown_needs_review` | 无法自动证明 | 放行，但进人工审查清单 |
| `not_applicable` | 本阶段无可比对对象 | 放行，明确说"不是通过" |

### 确定性检查怎么做的

| 特征类型 | 检查方法 |
|---|---|
| 空间（无柱/通透） | 在空间多边形内部统计墙与柱，排除贴边分隔墙 |
| 水景 | 在功能表与空间用途里查找水景类用途 |
| 种植 | 同上 |
| 顶面/灯光 | 读 S4 顶面与灯光成果，统计外露风口、明装、主灯 |
| 序列/走廊 | 检查交通空间是否仍存在 |
| 立面比例等观感 | 无确定性数据 → `unknown_needs_review` |

墙体判定踩过一个坑：一开始用包围盒，相邻空间共享一道墙，包围盒必然重叠，
于是"走廊边墙"被当成"私自加墙"。现在要求两端点都在多边形内部且都不贴边
（80mm 容差）。

### 三个真实案例

| 案例 | 人为制造 | 结论 |
|---|---|---|
| 建筑：无柱通透空间 | S4 插入一根柱 `C-DEMO` | `changed`——"客厅范围内出现 1 处墙/柱" |
| 室内：无主灯平顶 | 顶面成果写"外露风口 + 明装检修口 + 主灯吊灯" | `changed`——"2 处外露风口、出现主灯类做法" |
| 景观：庭院水景 | 功能表里没有水景类用途 | `changed`——"水景被取消或被改成旱景" |
| 反例：换墙面颜色 | 只改面层 | `acceptable_adjustment`，不重开门禁 |

证据在 `out/acceptance-round4/`。

## 六、G3–G8 各自的检查点

| 门禁 | 关注什么 |
|---|---|
| G3 | 平面是否违背概念的空间组织 |
| G4 | 建筑、室内、景观与主要技术方案是否保持设计意图 |
| G5 | 模型与视觉表现是否存在可验证的设计偏差 |
| G6 | 定稿前综合意图审核 |
| G7 | 正式深化成果是否与已批准基准一致 |
| G8 | 交付版本是否对应最后有效的批准状态 |

按实际委托范围启用：不在范围的专业不参与检查，标 `not_applicable`，
不用"通过"糊过去。

**成功保留原意图的技术调整不重开 G2**：只有真正改变核心特征才进变更审批。

## 七、仍须人工复核的判断

这些**永远不会**被自动判为通过：

| 项 | 为什么 |
|---|---|
| 立面比例是否舒展 | 无量化依据，属观感 |
| 材质观感与真实样板的差异 | 屏幕与实物不同 |
| 光影氛围是否达到预期 | 需现场或渲染图目视 |
| 结构计算与配筋 | 须注册结构工程师 |
| 机电负荷与消防合规 | 须专业工程师 |
| 规划指标符合性 | 须当地规范复核 |
| 空间体验是否"好用" | 依赖使用者行为 |

这些在一致性报告里一律 `unknown_needs_review`，并写明"未计入通过"。

## 八、还没做到的

- **语义级漂移**：词面与几何能查，但"把中式改成了日式"这类表述型漂移查不出来，
  只能靠主创看图。
- **跨版本对比**：目前对比"当前成果 vs G2 意图"，不做"S4 与 S5 之间"的逐版差异。
- **自动修复**：检测到 changed 只拒绝并给路径，不自动改回原设计。
- **视觉模型辅助**：未接入图像比对；接入后也只能作为**线索**，不能替代几何验证。
