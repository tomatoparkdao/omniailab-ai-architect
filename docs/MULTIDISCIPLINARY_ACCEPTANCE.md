# 多专业升级验收

## 一、证据等级先说明

六组案例全部是 `scripted_e2e`：客户由脚本代理应答，几何来自 demo 壳体。

**它证明的是引擎与门禁的行为，不是真实业主授权。** 脚本代理签的 G1–G8 只说明"门禁在校验真实条件"，不代表有人签过字。

## 二、六组案例结果

复现命令：`python scripts/acceptance_round3.py`，证据在 `out/acceptance-round3/`。

| 案例 | 范围判定 | 走到哪 | 卡在哪 | 卡的原因 |
|---|---|---|---|---|
| A 150㎡ 住宅室内装修 | 室内 + 结构 | S1–S6 全通 | **S7 阻断** | 结构条件未证实（客户说"不确定哪道墙承重"） |
| B 新建三层别墅 | 建筑+室内+结构+机电+景观 | S1–S6 全通 | **S7 阻断** | 无地勘、无结构方案 |
| C 独立庭院景观 | 景观（仅） | S1–S2 | **S3 阻断** | 无景观平面生成器 |
| D 酒店室内中庭 | 室内 + 景观 | S1–S3 | **G3 拒绝** | 所选原型无平面策略 |
| E 办公改造 | 室内+结构+机电 | **S1–S8 全通** | 无 | G1 先拦容量矛盾，客户决策后通过 |
| F 综合项目变更 | 五专业全开 | 3 项变更分析 | 未应用 | 只做影响分析，不自动改已确认基准 |

## 三、逐案说明

### A / B：S7 阻断是对的

```
U-STRUCTURAL（未知）：结构条件：有地勘/图纸缺失 → 施工图不得基于未证实的结构条件
```

施工图是拿去施工的。基于一个没核实的结构条件出图，后果比"没出图"严重得多。所以这两个案例停在 S7 是**设计正确**，不是缺陷。

补图后可继续：A 需要原结构图纸与承重墙确认；B 需要地勘报告。

### C：纯景观不许用房间算法

```
本次范围是景观：当前平面生成器只做建筑/室内的空间组织，
不能拿房间组合算法冒充专项方案。
```

这条拦截是本轮新加的。之前的版本会拿住宅 `band_day_night` 硬做，出来一张"很像平面图"的东西——那比没有图更危险。

### D：原型的边界

中庭案例选到的原型是「序列式到达」，它没有对应的 `plan_strategy`，G3 拒绝：

```
[G3-CONCEPT-CONFLICT] 平面与所选概念存在重大冲突
[G3-PROTOTYPE-UNSUPPORTED] 所选概念的空间原型没有对应的平面策略
平面可作为探索稿继续深化；正式 G3 须先解决以上条件。--force 不能绕过。
```

这是刻意保留的边界：S3 只实现 `band_day_night` / `spine_centre` / `office_cluster` 三种策略，其余原型走探索稿。

### E：唯一走完全程的案例，因为它的前提是真的

办公项目有物业图纸、核心筒与梁位清楚，所以结构条件成立，S7 能过。

它的价值在于展示了容量矛盾的正确处理路径：

```
G1 阻断：60 人 ÷ 132㎡ = 人均 2.2㎡，明显装不下
  → 客户决策：改为 25 人常驻，其余轮用工位
  → 重新判定：approved（人均 5.3㎡，仍属紧凑，写成条件）
  → S3 平面自己再算一次，一致性 pass
  → S4–S8 全通
```

**不是强行放行**：第一次 G1 是 `blocked`，客户做了具体取舍（不是点"同意"）才通过。

### F：跨专业变更

| 请求 | 领域判定 | 落点 | 牵动 |
|---|---|---|---|
| 院子里加一个泳池 | 景观与场地 | S3 | 结构、建筑、机电 |
| 屋顶改成花园 | 屋面与外立面 | S3（从 S4 提升） | 建筑、结构、景观、机电 |
| 客厅墙面换个颜色 | 材料与色彩 | S4 | 无（local，不返工） |

第三条和前两条同样重要：换颜色不该让结构和景观全部返工，否则变更引擎就没有可信度。

## 四、本轮修掉的真实缺陷

| 缺陷 | 现象 | 后果 |
|---|---|---|
| `scope.entry()` 有副作用 | 查询即创建 UNKNOWN 记录，UNKNOWN 又属于"在范围" | 凭空把没提到的专业拉进范围 |
| 否定按单字匹配 | 「别墅」的「别」被当成否定 | "带庭院水池的三层别墅"被判成**明确不做景观** |
| 否定跨分句泄漏 | "室内不动，院子做景观" | 后一句的景观也被否掉 |
| 专项委托被预设室内 | "只想重新设计花园" | 被问卧室数量与收纳需求 |
| 概念方向是通用文案 | 三套概念的结构立场是同一段话 | 等于三个 AI 各抄一份 |
| 比较维度无专业项 | 缺结构资料时仍给高分 | 用美学分掩盖硬性前提缺失 |

## 五、能力真实性（不许混为一谈）

| 说法 | 真实情况 |
|---|---|
| "能出结构方案" | **不能**。能出"这套概念要求结构回答什么" + 待核实清单 |
| "能算机电负荷" | **不能**。能出接口与设备条件 |
| "能出建筑施工图" | **不能**。S7 无建筑图纸适配器 |
| "能出室内施工图" | **部分**。有 DXF 平面与做法表，非持证签署 |
| "能出景观方案" | **不能**。S3 明确阻断 |
| "能核对规划指标" | **部分**。能列口径与缺口，不出法定结论 |
| "能判断变更影响" | **能**，且跨专业（6 类规则 + 12 组接口） |
| "能锁定多专业概念" | **能**，G2 逐专业锁定同一 concept_id，事务回滚 |
| "桌面端已集成" | **未连接**。无公开调用接口 |
| "画布已打通" | **未连接**。平台 `not_configured` |
