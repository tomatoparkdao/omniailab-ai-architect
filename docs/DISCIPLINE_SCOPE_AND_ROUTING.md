# 专业范围与路由

## 一、为什么先做这一层

真实委托里，“室内设计”只是其中一种。常见的是：

- 只做院子景观；
- 只做结构加固；
- 建筑与室内一体；
- 机电专项；
- 需要报批的新建。

旧实现默认所有项目都走“住宅/办公的房间组合”，于是纯景观项目被问“要几间卧室”，结构加固项目被要求“选一个风格”，新建建筑被当成装修做。

这一层只做三件事，**不产生任何几何**：

1. 定义项目涉及哪些专业，每个专业此刻是什么状态；
2. 把问题路由出去——不在范围的专业不许被追问；
3. 把“缺资料”和“缺专业签署”记成可追踪的状态。

## 二、五态：不要把“没问”当成“不用做”

| 状态 | 含义 | 能不能作为出图依据 |
|---|---|---|
| `declared` | 客户或任务书明确要做 | 能，但仍需资料 |
| `required` | 被其他专业的成果牵动，必须有 | 能，但深度未定 |
| `inferred` | 从描述推断，尚未确认 | 不能，须先确认范围 |
| `unknown` | 在范围内但资料不足 | 不能，只能给条件 |
| `out_of_scope` | 明确不做（**必须有证据**） | 不涉及 |

`out_of_scope` 只能来自客户原话或任务书声明。推断绝不把任何专业标成“不做”——这是这一层最危险的错误，因为“没提”和“不做”在后果上完全不同：不做景观，屋顶排水的风险并不会消失，只是没人管。

判定依据落进 `ScopeEntry.evidence`，写清是哪句话、哪个词触发的。否定语会双向识别：“不做室内”和“室内不动”都算明确不做。

## 三、新建信号

客户说“有块地、建三层别墅、带庭院水池”，字面没出现“建筑”两个字，但这是建筑委托，不是装修。

`NEW_BUILD_HINTS` 覆盖“新建 / 自建 / 地块 / 有块地 / 宅基地 / 建一栋 / 层别墅 / 报建 / 毛坯 / 土建”等。

命中时只标 `inferred`，不直接标 `declared`——因为“别墅”也可能是纯室内委托，需要客户确认一句：“建筑本体也在这次范围内吗？”

## 四、问题按范围路由

`route_question_slots()` 返回（需要问的槽位，被排除的槽位）。不在范围的专业，其专属问题不再出现。

专业专属问题只问“影响下一步能做什么”的事，不求把专业问全：

| 问题 | 归属专业 | 为什么问 |
|---|---|---|
| 结构是局部加固、拆改承重，还是新建？ | structure | 决定结构是咨询、复核还是必须出计算书 |
| 机电要做到点位核对，还是出系统图与管综？ | mep | 决定机电是配合提资还是独立出图 |
| 室外主要要铺装动线、种植、水景，还是屋顶花园？ | landscape | 景观分区与工程量都从这里来 |
| 需要报建吗？有容积率、退线、限高要求吗？ | planning | 涉及法定指标，缺了不能承诺方案可报 |

保留原有三条纪律：每轮最多三问、已答槽位不重复、依赖未满足不提前问。

## 五、接口矩阵：会打架的物理约束

`INTERFACES` 不是协作口号，是十二组具体冲突。只在**双方都在范围内**时进矩阵。

| 编号 | 涉及 | 冲突点 | 影响阶段 |
|---|---|---|---|
| IF-STR-SPACE | 结构 / 建筑 | 梁柱、剪力墙与挑空、通高、大开间 | S3 |
| IF-STR-LOAD | 结构 / 景观 | 屋顶花园、水景、大乔木的附加荷载 | S3 |
| IF-STR-OPENING | 结构 / 室内 | 拆墙、开洞、加夹层对承重体系 | S3 |
| IF-MEP-HEIGHT | 机电 / 室内 | 吊顶净高与风管、桥架、喷淋、排水坡度 | S4 |
| IF-MEP-WET | 机电 / 室内 | 卫浴移位与立管、地漏、防水 | S3 |
| IF-MEP-LAND | 机电 / 景观 | 景观照明、灌溉、水景循环与电气安全 | S3 |
| IF-WATER-FR | 建筑 / 景观 | 水池、种植池、屋顶绿化的防水与排水 | S3 |
| IF-FACADE-MEP | 建筑 / 机电 | 立面百叶、设备平台、通风开口 | S4 |
| IF-PLAN-FAR | 规划 / 建筑 | 容积率、退线、限高、日照与体量 | S2 |
| IF-PLAN-LAND | 规划 / 景观 | 绿地率、透水率、乔木覆盖率 | S3 |
| IF-IN-LAND | 室内 / 景观 | 室内绿化、中庭的日照、灌溉、排水、荷载 | S3 |
| IF-ARCH-IN | 建筑 / 室内 | 层高、梁底标高与吊顶、门窗洞口 | S3 |

每条含四件事：谁先给条件、需要什么才能定、**什么情况下算没解决**、影响哪个阶段。

第四项是关键。“建筑图上有跨越楼层的通高空间但结构未给出梁位”——这是可判定的失败条件，不是“建议加强沟通”。

有一方明确不在范围时，该接口进 `one_side_out`，并写明：“不做某个专业，风险不会消失，需确认由谁承担。”

## 六、S1 成果

范围非空时，S1 成果包追加六份：

| 文件 | 内容 |
|---|---|
| `discipline-scope.json` | 逐专业状态、依据、交付物、是否需签署，含接口 |
| `discipline-scope.md` | 人读版：这次涉及什么、明确不做什么、还缺什么 |
| `discipline-interface-matrix.json` | 接口矩阵与计数（active / one_side_out） |
| `discipline-interface-matrix.md` | 人读版：冲突点与失败条件 |
| `discipline-responsibility-matrix.md` | 系统能出到什么、必须人工复核什么、谁签 |
| `information-request-list.md` | 缺什么资料、找谁要、**要不到的影响** |

范围为空（连“装修”都没提到）时不生成。空表比没有更危险——一份“全部 not_applicable”的接口矩阵会被读成“已核对无冲突”。

## 七、G1 与 G2 的接线

| 门禁 | 做什么 |
|---|---|
| G1 | 摘要新增“本次设计范围”一节；范围内但资料不足的专业写成条件；结构在范围内时把“结构工程师”加进需人工复核清单 |
| G2 | 在范围内的专业若在选定概念里没有方向，出 `G2-DISCIPLINE-<id>` 阻断：多专业项目不能只确认其中一半 |
| S3 | 范围不含建筑/室内（或只有景观类功能项）时拒绝用房间组合算法出图，写明“不能拿房间组合算法冒充专项方案” |

## 八、还没做到的

- 结构与机电**没有执行器**：系统能出条件、接口与缺口清单，不能出结构计算或机电负荷。这是刻意的边界，不是待办。
- 景观没有独立平面生成器：S3 会明确阻断，而不是套用住宅房间算法。
- 规划指标只做口径与缺口核对，不出法定结论——指标须按项目所在地规范，由当地专业人员复核。
