# 设计主导权与设计意图保护

## 一、总设计师的定位

以建筑与空间美学为核心，以功能体验为基础，以工程技术为实现手段。

由此推出两条不对称：

| 类别 | 专业 | 职责 |
|---|---|---|
| 设计主导 | 建筑、室内、景观 | 定美学、定空间、定体验；有设计统筹权 |
| 技术支撑 | 结构、机电 | 研究如何实现；不主导形态 |

**不是平级、平均决策的关系。** 结构安全和机电可行当然重要，但它们的正确位置是
"研究怎么把这个设计做出来"，而不是"在概念阶段决定这个设计长什么样"。

### 三条不可突破

| 编号 | 内容 | 不能被谁换掉 |
|---|---|---|
| HC-SAFETY | 结构安全：承重、抗震、荷载须专业计算确认 | 美学 |
| HC-FIRE | 消防与强制性规范：疏散、防火分区、耐火等级 | 美学 |
| HC-PHYSICS | 经核实的物理限制：净高、坡度、排水、检修空间 | 美学 |

在满足这三条的前提下，最大限度保留设计意图。**主导权不等于豁免权。**

## 二、五种主导模式

主导不是按项目类型拍脑袋，是按"客户买的是什么设计"判断。

| 模式 | 名称 | 主导 | 判据 | 关键约束 |
|---|---|---|---|---|
| A | 建筑主导 | 建筑 | 有新建迹象 + 建筑在实据范围 | 结构机电不得在概念阶段主导形态 |
| B | 室内主导 | 室内 | 既有建筑 + 只委托室内 | 不为迎合机电而改已确认的室内美学；不重启建筑设计 |
| C | 景观主导 | 景观 | 只有景观在实据范围 | 不因水泵管线方便就取消核心水景；不调房间算法 |
| D | 建筑综合主导 | 建筑 | 新建 + 建筑/室内/景观同时在范围 | 室内与景观不是附属，是独立创造力 |
| E | 室内景观联合 | 室内 + 景观 | 既有建筑 + 室内与景观同时委托 | 不重启完整建筑；仅在涉及建筑本体时加建筑协调 |

### 「实据」是关键

`_firm()` 区分"真的在范围"与"被预设进来"：

- `interior` 可能因为"项目类型是住宅"被预设（弱证据）；
- `architecture` 可能因为"项目类型判为建筑类"被推断（弱证据）。

弱证据不能用来抢主导权。否则一个纯庭院委托会被判成"建筑主导"，然后被要求
先做整栋建筑设计——这正是本轮要修的病。

## 三、S1：按主导专业问诊

问题按**范围**路由（上一轮已做），本轮再按**主导**排序：

| 项目 | 先问什么 | 不该问什么 |
|---|---|---|
| 三层别墅 | 用地、建筑规模、功能、外观、空间体验、预算 | 不问室内收纳细节 |
| 已建成大平层 | 原始户型、生活方式、风格、材料、预算 | 不问用地红线、容积率、基础形式 |
| 庭院 | 面积、风格、活动、植物、水景、维护 | 不问室内精装与建筑立面 |

G1 摘要新增「设计主导与协作原则」一节，写清主导模式、谁有统筹权、
讨论顺序、三条不可突破。`design-leadership.json` 进 S1 成果包。

## 四、S2：概念以美学与创意为重点

### 权重由主导专业决定

`compare.py` 的维度权重不再是固定值，而是 `base × 主导系数`：

| 维度 | 建筑 | 室内 | 景观 |
|---|---|---|---|
| 美学与偏好 | 1.30 | 1.30 | 1.35 |
| 空间组织 | 1.25 | 1.20 | 1.20 |
| 需求响应 | 1.05 | 1.15 | 0.95 |
| 施工与维护 | 0.90 | 0.90 | 0.85 |
| 预算适配 | 0.90 | 0.90 | 0.90 |

含义很直接：建筑项目里"好施工"不该压过"造型与空间"；景观项目里
"美学与意境"权重最高。

### 两层评价

**第一层：硬门槛。** 安全、消防与强制性规范、已核实的容量与物理限制。
这一层不参与加权——**美学高分不能抵消它**。过不了门槛的方案 `rankable=False`，
排序时排在所有可行方案之后；全部方案都过不了时，报告会说：

> 本轮所有方案都没有通过硬门槛：请先解决上面列出的硬问题，
> 否则这不是选哪个方案的问题，是这个项目现在不成立

**第二层：设计价值。** 在可行方案之间，按主导专业加权比较。

### 技术深度只到概念级

S2 的结构与机电只回答三件事：大致体系方向、主要技术难点、大致机房与竖井位置。

不做：结构计算、负荷计算、设备选型、管径计算、配电系统、复杂管线综合。

原因不是"做不了"，是**不该在这时做**：概念阶段把技术细节做满，客户迟迟看不到
方案，而技术条件又还没确定，做了也要返工。

## 五、设计意图保护

### 为什么需要

技术和设计冲突时，最常见的不是争论，是**静默替换**：大跨度客厅"顺手"加两根柱，
无主灯天花"顺手"排满风口，水景"顺手"改旱景。每一次都说得通，加起来方案就没了。

### 基准内容

G2 时落 `design-intent-r<rev>.json`：

| 字段 | 内容 |
|---|---|
| `design_intent_id` | 由概念 ID + 主导专业 + 特征原文哈希得到 |
| `lead_discipline` | 谁的设计意图 |
| `design_principles` | 设计原则（来自照明方向与概念主张） |
| `signature_features` | 核心美学特征，逐条带原文与来源字段 |
| `protected_visual_elements` | 受保护的视觉要素 |
| `spatial_experience_goals` | 空间体验目标 |
| `acceptable_adjustments` | 可接受的调整范围 |
| `technical_dependencies` | 每条特征依赖什么技术条件 |
| `revision` | 修订号 |

特征**从概念自己的话里取**，不是套模板：

| 主导 | 取哪些字段 |
|---|---|
| 建筑 | spatial_logic / zoning / circulation / daylight |
| 室内 | zoning / circulation / daylight / experience |
| 景观 | spatial_logic / zoning / circulation / daylight |

没有依据的字段不写（少于 8 个字直接跳过），避免凑数。

### 触及判定：两条通道

1. **原文命中**：特征原文里的设计术语出现在改动请求里；
2. **同类触发**：请求提到该类型的关键动作（如「拆/打通」之于空间分区）。

第二条是保守方向——宁可多要一份说明，也不静默放过。但**面层级调整**例外：
"换个颜色"这类请求命中 `SURFACE_ONLY` 时不要求走技术路径，否则保护机制变成噪音。

## 六、技术冲突的六级顺序

不允许跳过任何一级。

| 级 | 做什么 | 硬规则 |
|---|---|---|
| 1 | 确认冲突是否真实存在 | 未经核实的猜测不得用来改设计 |
| 2 | 辅助专业提出**至少一种**保留原意图的技术路径 | 不能因为复杂就自动否定原设计 |
| 3 | 比较代价：外观、空间净高、技术复杂度、施工、造价、工期、复核需求 | 技术复杂但可行 ≠ 劣质设计 |
| 4 | 推荐最少损害美学的方案 | 满足安全与规范的前提 |
| 5 | 确不可行时提**最小必要修改** | 只改必须改的那一处，不顺带调整其他特征 |
| 6 | 重新影响分析与审批 | 不得覆盖已确认基准 |

### 技术路径是具体的

| 冲突类型 | 给的方向 |
|---|---|
| 大跨度 | 优化柱网把柱移到非焦点处 / 钢结构减小梁高 / 局部转换或预应力 / 梁上翻分配净高 |
| 悬挑 | 优化受力路径（根部加高、拉杆斜撑）/ 轻质构造 / 分段悬挑中间支承 |
| 天花与风管 | 隐蔽或线性风口 / 检修口整合进灯槽 / 设备移位管线绕行 / 设备装饰一体化 |
| 水景设备 | 设备下沉或外移 / 一体化循环机组 / 调整水面标高 |
| 种植荷载 | 轻质土与浅根植物 / 容器种植 / 分区承重 |
| 立面开口 | 调整尺寸分格 / 高透玻璃窄边框 / 进排风改走屋面侧向 |
| 拆墙 | **先确认是否承重** / 门洞加过梁 / 可开启隔断替代 / 局部开洞边柱加固 |

"拆墙"单独一类是刻意的：走承重判定，而不是柱网优化——两者代价差一个量级。

## 七、还没做到的

- **结构计算**：只给路径与条件，不出计算书。
- **成本量化**：能说"造价影响"是必须比较的一项，但没有分项估算。
- **意图的语义理解**：触及判定是词面匹配 + 类型触发，不理解"我想更通透"这类
  间接表达；这类需要主创判断。
- **G2 之后的意图漂移检测**：S4/S5 改动后没有自动比对意图是否变形。
